# 1. What does Parcel actually do?

Think of Parcel as a **build tool/bundler**.

You give it:

```text
App.tsx
components/
styles.css
images/
...
```

Parcel processes them:

```text
        Your source code
              │
              ↓
           Parcel
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
   JS bundle CSS      assets
      │
      └────────┬───────┘
               ↓
          Browser
```

Parcel's job is largely to:

* bundle modules
* transform TypeScript/JSX
* process CSS
* optimize assets
* serve the development application

It doesn't sit there doing:

```text
App.tsx
   ↓
"Hello Gopi"
   ↓
HTML
```

That's React's rendering job.

When you hear:

### **Bundling**

Think:

> "Take my modules/source code and prepare them for the browser."

### **Rendering**

Think:

> "Run React and determine/create the UI."

### **Server rendering**

Think:

> "Run the rendering work on the server instead of waiting for the browser."

### **Hydration**

Think:

> "Take the server-rendered UI and make the client-side React parts interactive."
